# Мини-курс в Telegram (3 урока + дожим через 24ч)

Бот шлёт пользователю 3 видео-урока по очереди. Каждый урок открывается только после клика по кнопке «Я просмотрел» на предыдущем. Через 24 часа после третьего урока приходит финальное сообщение со ссылкой на сайт.

## Стек

- Python 3.12, [aiogram 3](https://docs.aiogram.dev/)
- SQLAlchemy 2 (async): SQLite локально, PostgreSQL на Railway
- Long polling (без webhook), фоновый asyncio-таск для дожима

## Структура

```
bot/
├── main.py        # точка входа: запуск polling и фонового дожима
├── config.py      # настройки из .env (pydantic-settings)
├── content.py     # ВСЕ ТЕКСТЫ И ССЫЛКИ НА УРОКИ — правишь тут
├── db.py          # модель User + async-движок SQLAlchemy
├── handlers.py    # /start и обработка кнопок «Я просмотрел»
└── scheduler.py   # фоновый цикл, шлёт дожим через 24ч
```

## Что заполнить перед запуском

1. **Сбросить токен в @BotFather** (текущий был опубликован) → положить новый в `.env`.
2. В [bot/content.py](bot/content.py) заменить `REPLACE_ME_*` на реальные ссылки на видео и при желании поправить тексты/заголовки уроков.
3. В `.env` указать `SITE_URL` — ссылку, которая придёт в дожиме.

## Локальный запуск

```bash
cd "ТГ бот мини курс"
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env   # если .env ещё нет
# открой .env и впиши свой BOT_TOKEN и SITE_URL

python -m bot.main
```

База `bot.db` (SQLite) создастся автоматически.

### Быстрая проверка дожима

Чтобы не ждать сутки, временно поставь в `.env`:
```
FOLLOW_UP_DELAY_SECONDS=60
FOLLOW_UP_CHECK_INTERVAL=10
```
Тогда дожим придёт через минуту после клика «Я просмотрел» на 3-м уроке.

## Деплой на Railway

1. Залить проект в GitHub-репозиторий.
2. На [railway.com](https://railway.com) → **New Project → Deploy from GitHub** → выбрать репо.
3. В сервисе бота: **Variables** → добавить:
   - `BOT_TOKEN` — новый токен от @BotFather
   - `SITE_URL` — ссылка на сайт для дожима
4. В проекте: **+ New → Database → PostgreSQL**. Railway создаст переменную `DATABASE_URL` — её нужно прокинуть в сервис бота:
   - В сервисе бота → **Variables → New Variable** → `DATABASE_URL` → значение `${{Postgres.DATABASE_URL}}` (Reference).
5. Railway увидит `Procfile` (`web: python -m bot.main`) и запустит бота. Порт не нужен — бот работает на long polling, предупреждение о «no exposed port» можно игнорировать. При желании в **Settings** сервиса переключить тип на *worker*.
6. Готово. При каждом push в основную ветку Railway будет автоматически передеплоивать.

### Важно
- **Только один экземпляр бота.** Telegram long polling не терпит две копии с одним токеном — будет конфликт. На Railway держи replicas = 1.
- Если позже захочешь перейти на webhook (нужен публичный URL и порт) — это правка только в `bot/main.py`, остальное не меняется.

## Как работает стейт пользователя

В таблице `users` хранится поле `lessons_watched` (0..3):

| Состояние | Что происходит |
|---|---|
| 0 | `/start` → шлём приветствие + урок 1 (кнопка «✅ Я просмотрел») |
| 1 | клик «Я просмотрел» на уроке 1 → шлём урок 2 (кнопка «✅ Я просмотрел») |
| 2 | клик «Я просмотрел» на уроке 2 → шлём урок 3 (кнопка «🔥 Хочу на курс»), пишем `lesson3_sent_at` |
| 2 + прошло 24ч | фоновая задача шлёт ссылку на сайт (дожим), ставит `follow_up_sent_at` |
| 3 | клик «🔥 Хочу на курс» → моментально шлём ссылку, ставим `follow_up_sent_at` (дожим больше не уйдёт) |

Если на 3-м уроке юзер сразу нажал «Хочу на курс» — он получит ссылку сразу и дожима не будет. Если не нажал — через 24ч ему всё равно прилетит ссылка автоматически. Клики по «старым» кнопкам игнорируются.

## Если бот упадёт / Railway передеплоит
Состояние хранится в БД, фоновый цикл при старте сам подберёт всех, у кого подошёл срок дожима. Ничего не теряется.
